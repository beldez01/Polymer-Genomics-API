Internal source review of batch 0 covers three articles, not the whole library. Interface verification and independent scientific sign-off remain separate.

## Evidence workflow and review handoff

Create a private record under `viewer/docs/editorial/` for each article or shared revision batch. Use these fields:

| Field | Required content |
| --- | --- |
| Identity | Research-map brief IDs, proposed/stable slug, central question, audience prerequisites, draft date. |
| Claim | Exact proposed claim and location in the draft; classify as observation, model, historical inference, synthesis, or hypothesis. |
| Source | Stable dossier ID plus full bibliographic identity, DOI/primary URL, and exact result/figure/method/supplement location. Local source IDs may differ; record the crosswalk. |
| Scope | Organism, cell type, intervention, conditions, sample/replicate definition, assay, scale, and relevant controls. |
| Verification | Full-text/supplement reading status, corrections/retractions, later tests or challenges, and dated 2025–2026 search record. Inaccessible evidence remains a documented blocker. |
| Inference limit | What the result supports, alternative explanations, and language or quantitative claims it does not justify. |
| Figure/calculation | Original design, inputs, units, assumptions, synthetic/schematic labels, numerical verification, and accessible text equivalent. |
| Review | Open questions, reviewer decision when actually obtained, and unresolved publication blockers. |

A source-register entry is a lead, not a completed claim record. Attach citations to the claims they support; where the present renderer only supports section citations, keep sections narrowly scoped and explain differing source contributions in prose. Additional sources receive new stable IDs in an extension record; preserve existing IDs and the original dossier.

Before drafting a full treatment, resolve the source-expansion gates in the table. Before implementation, complete the claim record, original figure specification, and tool-link verification. Before public publication, obtain scientific review and resolve the editorial license identified in the existing library documentation. Do not invent authorship or mark an article reviewed because its interface builds.

## Special handling of the boundary-erosion hypothesis

Brief 40 must open with an explicit statement that LINE-1 interior localization, ERV edge enrichment, outside-in heterochromatin failure, and universal ERV-before-LINE-1 activation are not established by the dossier. “Melting” is an analogy unless a physical transition is measured. Do not use an asserted edge/interior arrangement as the factual illustration for briefs 37–39 or 41–42.

Its original figure should show competing predictions rather than a single causal cartoon. The research-design section must specify:

1. One prespecified boundary definition and the cell type/senescence model; keep organismal aging distinct.
2. Baseline boundary distance measured before activation, with linear and 3D measures distinguished.
3. Locus/subfamily/age/intactness resolution, including solo LTRs and truncated copies; quantify mappability and multi-mapping uncertainty.
4. Longitudinal matched RNA/chromatin data and controls for GC/CpG, gene distance, length, baseline repression/expression, replication timing, and activator motifs.
5. Within-family tests before between-family interpretation; biological replicate/donor inference and spatially aware null models.
6. Comparisons against activator induction, silencing dependencies, copy age, baseline accessibility, and detection bias; account for transcription changing the apparent boundary.
7. An architectural intervention before claiming causality. A reproducible distance association alone does not establish the proposed mechanism; a controlled null result must remain reportable.

Distinguish expression, reverse transcription, sensing, particle production, and new insertion throughout. Recover exact primary references before adopting numerical genome fractions or isochore/band claims from user-supplied conceptual passages.

## Library integration

Keep the existing eight-foundation order and stable routes. Initially append new foundations with explicit order values and place physical/methodological references in the existing `reference` collection. Editorial reading paths can use related links and introductions while the first batches are drafted.

The current type supports only `foundations` and `reference`, one collection per article, and a fixed figure-kind union. Named thematic collections are therefore a later implementation task, not a current capability. Once a second substantial batch is ready, propose a small reading-path structure that references existing slugs, supports one article in multiple paths, and keeps the existing collection/order contract. Do not put unpublished briefs into public search or create empty categories. Add Origins & evolution as a subject only with its first implemented article.

Use imported article modules under `viewer/src/content/library/`; preserve the aggregate registry. New interactive figures require a renderer/type addition and meaningful calculation checks. Prefer original code-native diagrams and accessible tables. Do not introduce a CMS or API dependency for editorial content.

Tool connections are optional. Verify actual routes, assemblies, layers, provenance, and model status in the implementation before linking. Origins essays need no artificial tool demonstration. Do not present the tabled nucleosome occupancy model as a validated measurement or infer that a proposed conceptual layer exists in the API.

For each implemented batch: update the sitemap for new routes, related links, metadata, search terms, and library documentation. Run the existing TypeScript/build checks and review citation anchors, related navigation, filtering, missing routes, keyboard interaction, and narrow-screen layouts. Numerical interactive figures also require independent expected-value checks. These checks validate implementation, not scientific conclusions.
